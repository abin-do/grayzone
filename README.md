# grayzone

세션 로그 / 서사 로그 / 커미션 이미지 / 캐릭터 백업 + 비주얼노벨 스타일 메인페이지.

`src/content/` 아래에 정해진 형식으로 폴더만 추가하면 목록/상세 페이지가 자동으로 생성됩니다. 코드를 건드릴 필요 없습니다.

## 로컬 실행

```bash
npm install
npm run dev
```

## 배포 (GitHub Pages)

1. 저장소 Settings → Pages → Source를 **GitHub Actions**로 설정합니다 (최초 1회).
2. `main` 브랜치에 push하면 `.github/workflows/deploy.yml`이 자동으로 빌드/배포합니다.
3. 배포 주소: `https://<계정명>.github.io/grayzone/`

저장소 이름을 바꾸면 `vite.config.js`의 `base` 값도 `/새이름/`으로 함께 바꿔주세요.

## 콘텐츠 추가 방법

### 세션 로그 백업 — `src/content/sessions/<폴더명>/`

| 파일 | 설명 |
|---|---|
| `meta.json` | `{ "title", "synopsis", "director", "cast": [], "releaseDate": "YYYY-MM-DD" }` |
| `card.*` | 목록 썸네일 (jpg/png/webp 아무거나, 원본 비율 유지됨) |
| `log.html` | 실제 로그 내용 |
| `synopsis.txt` (선택) | 개요가 여러 문단이면 이 파일을 만들어서 쓰세요. 그냥 엔터로 줄바꿈하면 됩니다. 이 파일이 있으면 `meta.json`의 `synopsis`보다 우선됩니다. |

폴더만 추가하면(파일명 규칙만 맞으면) 목록에 바로 나타납니다 — 코드 수정도, 등록 절차도 없습니다.

목록은 `releaseDate` 기준 최신순으로 정렬됩니다.

> ⚠️ `meta.json`의 `synopsis` 필드 안에서는 엔터(줄바꿈)를 직접 칠 수 없습니다 — JSON 문법이 깨져서 사이트 전체가 안 뜨게 됩니다. 여러 줄로 쓰고 싶으면 위의 `synopsis.txt`를 쓰세요.

`log.html`이 처리되는 방식은 서사 로그 백업과 동일합니다 — 아래 "로그 파일(log.html) 자동 인식" 참고.

### 서사 로그 백업 — `src/content/narratives/`

가장 간단한 방법: **폴더 없이 `.html` 파일을 `src/content/narratives/` 바로 아래에 놓기**. 파일 이름이 그대로 제목이 됩니다 (예: `0627.html` → 목록에 "0627"). 목록은 카카오톡 채팅 목록처럼 제목만 나열되고, 클릭하면 그 파일 내용이 상세 페이지에 나옵니다.

제목을 따로 지정하고 싶거나 순서를 정하고 싶으면 폴더 방식도 됩니다 — `src/content/narratives/<폴더명>/`

| 파일 | 설명 |
|---|---|
| `meta.json` | `{ "title", "order": 1 }` (선택 — 없으면 폴더명이 제목이 됨) |
| `log.html` | 실제 내용 |

### 로그 파일(log.html) 자동 인식

`log.html`에 뭘 넣든 아래 순서로 자동 판별해서 알아서 가장 알맞은 방식으로 보여줍니다. 그냥 파일을 그대로 넣으면 됩니다.

1. **Roll20 "Chat Archive" 내보내기** — 캐릭터 얼굴 아바타 + 이름 + 대사가 카카오톡 메시지처럼 자동으로 다시 그려집니다. 나레이션(`/desc`)은 가운데 정렬 텍스트로, 타이틀 아트 같은 삽화는 그대로 보존됩니다. 귓속말/GM 전용 메시지는 자동 제외됩니다. (Roll20 원본은 흰 배경을 가정한 어두운 글자색이 하드코딩되어 있어서 그대로 넣으면 글씨가 안 보이는데, 이 자동 변환이 그 문제를 해결합니다.)
2. **`.message-block` / `.bubble-name` / `.bubble-text` 클래스를 쓰는 카카오톡 스타일 채팅 HTML** — 개인적으로 만든 채팅 로그 템플릿도 같은 방식(아바타+이름+말풍선)으로 자동 인식되어 그려집니다.
3. **`<!DOCTYPE html>`로 시작하는 완전한 HTML 문서** (자체 `<style>`을 가진, 독립 실행 가능한 페이지) — 안전하게 격리된 `<iframe>` 안에 원래 디자인 그대로 표시됩니다. 이렇게 하는 이유: 그 페이지의 CSS가 우리 사이트 전체의 배경/글자색까지 덮어써버리는 걸 막기 위해서입니다.
4. 그 외 일반 HTML 조각(직접 만든 간단한 로그 등)은 그대로 삽입되어 렌더링됩니다.

**메인페이지 대사 기능과 연동**: 메인페이지는 서사 로그 백업에 있는 모든 대사 중 하나를 랜덤으로 보여줍니다. 위 1·2번 형식은 화자 이름을 자동으로 알아내고, 4번(일반 HTML)에서 특정 문단을 특정 캐릭터의 대사로 지정하고 싶으면 `data-speaker="이름"` 속성을 붙이면 됩니다 (예: `<p data-speaker="범태정">...</p>`). 화자 이름이 캐릭터 백업의 `name`과 일치하면 해당 캐릭터의 `standing.*` 이미지도 함께 표시됩니다. `data-speaker`가 없는 문단은 화자 없는 나레이션 대사로 취급됩니다.

### 캐릭터 백업 — `src/content/characters/<폴더명>/`

| 파일 | 설명 |
|---|---|
| `meta.json` | `{ "name", "role", "bio", "tags": [], "relationships": [{ "name", "description" }] }` |
| `portrait.*` | 목록 카드용 세로 이미지 |
| `standing.*` | 메인페이지 비주얼노벨용 전신 스탠딩 이미지 (선택) |

### 커미션 / 이미지 백업 — `src/content/gallery/`

가장 간단한 방법: **`src/content/gallery/img/` 폴더에 이미지 파일을 그냥 넣기만 하면** 메타데이터 없이 자동으로 갤러리에 나타납니다 (파일명 역순 정렬). 제목/설명/날짜가 필요 없는 일반 이미지 덤프용입니다.

제목·설명·날짜를 붙이고 싶은 이미지는 기존처럼 폴더 하나에 넣어주세요 — `src/content/gallery/<폴더명>/`

| 파일 | 설명 |
|---|---|
| `meta.json` | `{ "title", "caption", "date": "YYYY-MM-DD" }` |
| `image.*` | 그리드에 표시될 이미지 |

이 방식은 `date` 기준 최신순으로 정렬되고, `img/` 폴더에 넣은 이미지들보다 뒤에 표시됩니다.
